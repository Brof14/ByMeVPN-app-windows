# ByMeVPN Windows — аудит паритета Android и инженерных рисков

**Дата:** 06.11.2026  
**Android reference:** `Brof14/ByMeVPN-app`, ветка `main`, Jetpack Compose `app/src/main/kotlin/com/example/bymevpn/` (а не legacy Flutter `lib/`).  
**Windows target:** `Brof14/ByMeVPN-app-windows`, Tauri 2 / Rust / WebView2, PR #13.  
**Статус:** улучшенный UI и регрессионные тесты; **полный паритет и пригодность VPN для production НЕ подтверждены**.

## 1. Главный вывод

На уровне исходников у Windows уже есть многие аналоги Android-экранов и запросов к API, но исходный UI был ориентирован на широкий desktop-dashboard с боковой панелью, а Android — на мобильный одноколоночный экран с нижними вкладками. PR #13 приближает геометрию и навигацию. Экранное pixel-perfect совпадение, скорость, надёжность и сетевую безопасность невозможно подтвердить только чтением кода: нужны сборки и проверка на реальной Windows 10/11 с VPN-драйвером, сетевыми интерфейсами и тестовым аккаунтом.

### Стек и архитектура

| Компонент | Android | Windows | Статус |
| --- | --- | --- | --- |
| UI | Jetpack Compose Material 3 | HTML/CSS/JS в WebView2 | Один набор базовых цветов и изображения щита, но разная технология рендеринга |
| Навигация | Главная / Настройки / Аккаунт снизу | Ранее боковая Главная / Аккаунт / Настройки | **Исправлено в PR #13**: нижние вкладки, вложенные экраны сохраняют родительскую вкладку |
| VPN | Android VPNService + libv2ray/Xray | Rust-управление процессом Xray и Wintun | Только частичный паритет протоколов; TUN, маршруты и аварийная защита требуют практической проверки |
| Google | Android Credential Manager | Браузерный Desktop OAuth с PKCE и backend exchange | Код есть, end-to-end Windows OAuth не проверен |
| Telegram | Авторизация через Telegram с серверным подтверждением | Создание/опрос тикета и нативная внешняя ссылка | PR #13 устраняет блокировку сценария при отказе открытия браузера |
| Email | Email/password через backend | Email/password через backend | Внешний backend и ошибки требуют реального acceptance |
| Подписка/триал | Server-authoritative состояние и 3-дневный trial | `/subscription/status`, `/subscription/trial` | Есть интеграция, но нужна проверка entitlement и сервера после оплаты |
| Тарифы/оплата | Server-owned SKU, YooKassa | `/mobile/v2/plans`, `/mobile/v2/payment/create` и `check` | Не считать оплаченной до подтверждения счета от сервера |
| Устройства | Перечень / лимит / отключение | `/devices`, отключение через сервер | UI отображает реальный лимит, но доступность backend операций не гарантирована |
| Язык | RU/EN/System | RU/EN (отдельный PR #12 добавляет System) | PR #13 расширяет RU/EN для вложенных экранов, **не** заменяет PR #12 |
| Настройки | Минималистичные авто-подключение, RU bypass и язык | Больше desktop-настроек: автозагрузка, DNS, фильтрация, ограничения сервисов | PR #13 не выдаёт непроверенные системы защиты за действующие |

## 2. Что исправлено в PR #13

1. Центрированный одноколоночный интерфейс и нижняя навигация, адаптация к 800×590 / 960×700. Сохранён собственный заголовок окна; переписывание Tauri/Rust не требуется.
2. Порядок вкладок Android: **Главная / Настройки / Аккаунт**; корректное состояние выбранной вкладки во вложенных разделах и `aria-current`.
3. Идентичный исходный ассет shield используется как прежде; уплотнение UI не требует новой графики.
4. RU/EN-переводы основных вложенных страниц «Устройства», «Автопродление», «Помощь», «Дополнительные настройки»; исправлена версия интерфейса до 1.2.3.
5. Удалён неиспользуемый устаревший диалог с ложным сообщением, что Google отключён.
6. Исправлены ложные FAQ/платёжные утверждения: нельзя обещать идеальную неразличимость Reality-трафика, «нет CAPTCHA», гарантированную отмену автосписаний кнопкой или 1 Гбит/с без проверки.
7. Windows startup: при ошибке записи локальных настроек отменяется уже сделанное изменение автозапуска, чтобы UI и состояние Windows не расходились.
8. Telegram: отказ открытия внешнего браузера не завершает действующий тикет и его polling; можно повторить открытие.
9. Модальные окна: `role=dialog`, `aria-modal`, начальный фокус, закрытие по Escape, Tab-cycle, возврат фокуса к исходной кнопке; переиспользуются для legal modal.
10. Добавлены Node регрессионные тесты порядка вкладок, локализации версии, Telegram retry и отката автозапуска.

## 3. Регрессии и риски по приоритетам

| Приоритет | Риск | Текущее состояние | Приёмка |
| --- | --- | --- | --- |
| P0 | Привилегированный UI | `src-tauri/build.rs` запрашивает admin для всего приложения, включая WebView | Непривилегированный UI + отдельный подписанный service/helper с ACL IPC |
| P0 | DNS/IPv6/маршрутизация | Имеются настройки Xray TUN и пробы egress IPv4, но этого недостаточно для leak-proof | Leak-тесты IPv4, IPv6 и DNS, включение/срыв сети, перезапуск, краш и восстановление маршрутов |
| P0 | Kill Switch | Не реализован как надёжная системная WFP-политика; UI честно выключен | При обрыве туннеля нет ни одного незашифрованного пакета (кроме явно исключённых), доказать на Windows |
| P0 | Выход из приложения | Rust останавливает Xray при выходе, но ОС-маршруты и сбой питания не проверены | Reboot/uninstall/crash; отсутствие остаточных драйверов/правил маршрутизации |
| P0 | Авторизация/платёж | Нужны боевые Windows проверки Google, Telegram, email и backend invoice-specific webhook | Один реальный сценарий каждого типа + отклонения, повторы, logout и рестарт |
| P1 | Протоколы | Xray TUN Windows путь ограничен совместимыми нодами (в частности Reality/VLESS), Android поддерживает больше | Таблица всех production нод; подключение, отключение, reconnect и недоступный протокол |
| P1 | Pixel parity | CSS адаптирован под компактную ширину и нижние вкладки, но **не** сравнен скриншотами | Сопоставление Android Compose и Windows скриншотов каждого экрана/состояния |
| P1 | i18n | RU/EN расширены, но тексты части secondary/legacy элементов и серверных ошибок остаются русскими | Автотест ключей + ручной аудит каждого видимого элемента на EN и RU |
| P1 | Аккаунт / устройства | Список зависит от backend, ошибки могут быть временными | Тесты 0/1/максимум устройств, текущий девайс, отключение другого, ошибка API |
| P1 | Production updates | Нужны подпись и проверенный lifecycle NSIS/MSI и rollback | Чистая установка, обновление, удаление и проверка driver/runtime SHA |
| P2 | Производительность | **Нет замеров** RAM/CPU/latency/startup | Замеры x64 Windows 10/11, 100 циклов connect/disconnect, 100/150/200% DPI |
| P2 | Доступность | Исправлены клавиатурные диалоги и tab marker, но screen reader не проверялся | NVDA, Tab order, масштабирование текста, contrast и reduced motion |

## 4. Аудит потоков — чек-лист перед запуском

- **Авторизация:** первая установка → регистрация → логин → logout → Google Desktop browser OAuth → Telegram одноразовый ticket → отмена/таймаут → offline → токен истёк.
- **Доступ:** нет тарифа → пробный период 3 дня → просрочен → активный тариф → неизвестный статус сервера. Не отображать «VPN защищён» по запуску процесса: подтверждение IPv4-адреса не доказывает DNS/IPv6 безопасность.
- **VPN:** авто/выбор локации, неподдерживаемый узел, disconnect во время подключения, переключение узла при активном VPN, возврат с sleep/wake, Wi-Fi/ethernet switching, offline/reconnect, crash Xray и приложения.
- **Платежи:** цены получены от API, прайс для 2/5/10 устройств, idempotency request ID, реальный invoice, платёж отменён/ожидает/выполнен, подтверждённое продление. Не трактовать возврат из браузера как оплату.
- **UI:** окна 800×590, 960×700, 1280×800; DPI 100%, 150%, 200%; русский/английский, ввод длинного email и большого текста, Tab/Shift+Tab/Enter/Escape, модальные окна и прокрутка.
- **Установка:** скачать из CI настоящий подписанный/проверенный installer, сверить SHA256, проверить наличие Xray/Wintun в ресурсах относительно executable, clean Win10/11; удаление должно восстановить маршруты.

## 5. Фактические проверки и ограничения

**Проверяется автоматически в GitHub Actions:** `node --check ui/app.js`, `node --test tests/*.test.mjs`, `cargo check`, `cargo test --release`, сборка Tauri NSIS/MSI и smoke упаковки runtime. **Результат конкретного запуска смотреть по PR checks.**

**Не проверялось в этом изменении:** реальное подключение VPN на устройстве Windows, утечки, наличие WFP Kill Switch, фактический расход CPU/RAM, производительность рендера, screenshot diff с Android, реальная успешность Google/платежей. Нельзя выставлять оценки «10/10», «без багов» или «готово к production» без этих данных.

## 6. Что нужно до настоящего 1:1

- Сопоставить экран за экраном на одних и тех же серверных тестовых данных: авторизация, регистрация, Home без плана / offline / connected / error, серверы, тарифы, trial, аккаунт, устройства, настройки, advanced, помощь, управление продлением.
- Отдельно реализовать оставшийся Windows-native функционал, не переносимый прямым копированием Kotlin: Wintun/TUN, защищённое восстановление маршрутов, WFP Kill Switch, сервис с минимальными правами и crash recovery.
- Сохранить Rust backend, запретить любые mock-подписки/тарифы/узлы в production; оставить mock только в `qa-preview/`.
- Провести независимый security review нативных прав, CredMan секретов, логов Xray и приватных конфигов, а также серверных прав и платежей.

**Решение по релизу:** держать как экспериментальный Windows Preview, пока P0 пункты не пройдут физическую проверку. Этот аудит фиксирует проверенные по исходникам изменения, а не сертификат сетевой безопасности.
