# ByMeVPN Windows ↔ Android: проверяемый аудит и границы готовности
**Дата:** 2026-11-06
**Эталон:** `Brof14/ByMeVPN-app/main`, актуальная реализация Jetpack Compose — `app/src/main/kotlin/com/example/bymevpn/`.
**Цель изменений:** `Brof14/ByMeVPN-app-windows`, Tauri 2 / Rust / WebView (HTML/CSS/JS).

> Аудит исходного кода, а не сертификат безопасности, проверка пиксельной идентичности или подтверждение реального VPN на Windows. Состояние устройства, драйверов и production API не измерялось. Баллы ниже — редакционная инженерная оценка, не результаты бенчмарков.

## Методика
Проверены дерево двух репозиториев и основные Android-файлы: `theme/Color.kt`, `screens/{Home,Account,Settings,Pricing}Screen.kt`, `components/ServerSelectionSheet.kt`, `vpn/VpnManager.kt`, `data/settings/SettingsRepository.kt`, `data/api/ApiConfig.kt`. В Windows: `ui/{index.html,styles.css,app.js}`, `src-tauri/src/{service,tun_config,google_desktop,api_transport}.rs`, `src-tauri/tauri.conf.json`, существующие тесты, CI, руководства и предыдущие инженерные аудиты.

Критически важно сравнивать активную папку Android `app/`, а не устаревшие Flutter `lib/` и `android/` или `public/assets/aistudio` (референсные макеты).

## Конкретные выявленные дефекты и изменения
1. **P1 — ручная смена узла была визуальной, а не сетевой.** До правки обработчик `.server-stack-item` менял `state.selectedServer` и `selectedServerCode`, но не вызывал `vpn_stop` / `vpn_start`. Изменено в `ui/app.js` через один `selectServer()` с сериализацией операции. Ошибка native stop сохраняет предыдущий узел.
2. **P1 — гонка завершившегося VPN и позднего `vpn_status`.** Инкрементируемая `vpnSequence` и `sessionEpoch` предотвращают устаревшее перезаписывание состояния. Для polling используется идентификатор конкретного интервала.
3. **P1 — ошибка подключения исчезала вместе с toast.** Добавлена доступная `role=alert` строка `#home-connection-error`; сообщение очищается при новом переключении.
4. **P2 — неработающая интерактивная плашка маршрутизации.** `btn-toggle-bypass-quick` теперь ведёт в Settings, показывает выбранный bypass и доступен с клавиатуры.
5. **P2 — серверы нельзя было явно обновить из списка.** Добавлена `btn-refresh-servers` с блокировкой повторной загрузки, пока запрос не завершён.
6. **P2 — ввод поиска находил только RU-поля.** Поиск охватывает display name, страну, город на обоих языках и код.
7. **P1 — маркетинговые преувеличения в тарификации.** Убраны безусловные утверждения про отсутствие задержек, «полную маскировку», Hysteria2 на Windows; добавлен честный текст о доступных протоколах/ограничениях.
8. **P2 — часть тарифов и блоков без RU/EN.** Добавлены 20 пар строк; плановые карточки получили доступное состояние `aria-pressed` и отключение недоступных предложений.
9. **P2 — ошибки потери фокуса / масштабирования интерфейса.** Усилены `focus-visible`, состояние disabled, перенос строки на узких размерах окна.

## Что остается блокирующим перед стабильной публикацией

**P0 — безопасность и корректность Windows VPN:**
- Разделить повышенные привилегии (сейчас Tauri/WebView запускается от администратора) и обычный интерфейс: отдельный подписанный Windows Service с ограниченным IPC.
- Проверить Wintun и IPv4+IPv6 системные маршруты, DNS и WFP на Windows 10/11 после подключения, при обрыве сервера, отключении сети, sleep/resume и аварийном выходе процесса.
- Настоящий Kill Switch: WFP policy fail-closed, проверка исключений и гарантированное удаление правил при uninstall/rollback.
- Доказать что Xray скомпонован, находится по ожидаемому пути, проходит self-test и создаёт полноценный Windows TUN; проверка SHA-256 одного исполняемого файла не заменяет испытание туннеля.
- Подписанные установщики, обновления/откат и безопасный uninstall.
- Проверка API c реальной учётной записью: OIDC, Telegram, платежи, trial, devices, отзыв сессии, продление/автосписания.

**P1 — полная идентичность:**
- Не хватает Hysteria2 и других протоколов, поддерживаемых Android; не выдавать эти узлы за рабочие.
- Pixel-diff и ручная проверка всех состояний, системного шрифта, отступов, анимаций, контрастности и адаптивности на 800×590 / 960×700 / 1920×1080, DPI 100/150/200%.
- Windows tray, автоподключение и восстановление соединения после сна/изменения сети; настройки автозапуска привязаны к Windows.
- Сравнить все динамические и статические сообщения на RU/EN; Android также поддерживает вариант `system`.
- Реальные метрики CPU/RAM/времени запуска/пинга/скорости на одинаковой машине и сети: без измерений оценивать «нет лагов» нельзя.

## Приёмочные сценарии
1. Запустить стандартный Windows installer на чистых Windows 10 и 11 x64; проверить UAC/права/ресурсы/закрытие приложения.
2. Пройти Email, Telegram, Google, отмену входа, logout и повторный вход.
3. Без тарифа: активация 3 дней; активная/истёкшая/неизвестная подписка; лимит устройств 2/5/10.
4. Отключён VPN → запуск → проверка реального IP + IPv4/IPv6/DNS маршрутов; сменить сервер при активном туннеле; повторить 100 циклов.
5. Проверить error/retry, отключение питания/сети, Wi-Fi↔Ethernet, sleep/resume, Xray crash, восстановление маршрутов при shutdown.
6. Проверить YooKassa реальным sandbox счетом; при отмене и просрочке отсутствует фиктивное подтверждение.
7. Зафиксировать screenshot-критерии для 16 Android-референсов против всех Windows экранов, клавиатуру, screen reader и RU/EN.

**Вывод:** предложенные изменения адресуют проверяемые UI/state дефекты, но **не закрывают** системные ограничения Windows, функциональную разницу протоколов и отсутствие физического E2E. Пока нельзя маркировать Windows «полностью идентичен Android» или «production-ready».
